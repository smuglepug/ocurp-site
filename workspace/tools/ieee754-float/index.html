IEEE 754 Float Decoder

MATH — CLIENT-SIDE

What a floating-point number actually looks like in memory. Type a decimal and the page writes it into a real typed array, then reads the sign, exponent and mantissa back off the bit string — the way the hardware does it, which is why denormals and infinity fall out correctly instead of being special-cased. The exact value the bits hold is printed beside the number you typed, so the rounding error is visible rather than implied.

Fields
Bits — sign, exponent, mantissa, in colour

The real value the stored bits actually represent is printed next to the decimal you typed, because they are rarely the same number: 3.14159 in single precision comes back as 3.141590118408203. That gap is the rounding error, and hiding it is how a page ends up claiming an exact value it does not hold. Denormals and infinity are handled by the same code path, not by a special case that guesses.
